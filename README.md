# 📝 オンライン原稿用紙 Pro (サーバーレス・P2P版)

「オンライン原稿用紙 Pro」は、GIGAスクール構想のタブレット端末に最適化された、ブラウザ上で動く**縦書き原稿用紙＋作文添削アプリ**です。

児童は横書きの入力欄に打ち込むだけで、隣に**縦書きの原稿用紙**がリアルタイムに組版されます。先生は提出された作文を**原稿用紙の上で直接なぞって赤ペンを入れ**、その場で児童の画面に返せます。

バックエンドサーバーやデータベース（GAS等）は一切使いません。**PeerJS（WebRTC）による端末間の直接通信**と**ブラウザのローカルストレージ**だけで動作します。GitHub Pages 等に静的ファイルを置くだけで、その日の授業から使えます。

- **デモ / 配布元:** リポジトリを GitHub Pages で公開すればそのまま動きます
- **くわしい操作手順:** [📖 MANUAL.md（操作マニュアル）](MANUAL.md)

## ✨ このアプリでできること

### 🏫 先生と児童をつなぐリアルタイム通信（P2P）

- **4桁のPINコードだけで接続**
  先生が「通信ルームを開始」を押すと4桁のPINが発行され、児童はそれを入力するだけでつながります。アカウント登録・ログインID・メールアドレスは一切不要です。
- **提出後は書き直しがその場で先生に届く**
  一度提出された作文は、児童が書き直すたび（入力が止まって約0.6秒後）に自動で先生の画面へ送られます。先生側の原稿用紙も自動で最新の状態に更新されます。
  ※**提出前の下書きは先生の一覧には表示されません。** 名簿に並ぶのは「提出済」「再提出」「完了」の作文だけです。
- **切断・翌日でも取りこぼさない**
  通信が切れている間に先生が付けた添削は、児童が次に接続した瞬間に自動で返却されます（同じ端末・同じブラウザで開いた場合）。

### ✍️ 児童向けに最適化された画面

- **入力欄と原稿用紙の同時表示**
  左（スマホ・タテ画面では上）の入力欄に打つと、右の原稿用紙プレビューが即座に組版されます。入力欄をスクロールすると原稿用紙側も連動します。
- **本格的な原稿用紙の組版**
  20字×20行（高学年）／15字×16行（低学年）を切り替え可能。禁則処理は「追い出し」と「ぶら下がり」から選べ、「。」」のような約物は1マスに詰めて表示します。
- **ふりがな（ルビ）付きのやさしい画面**
  児童が使う画面のボタン・見出し・メッセージの漢字にはふりがなが振ってあり、低学年でも読めます（先生用の管理画面と、作文本文にはルビは付きません）。
- **文字数カウンター**：改行を除いた本文の文字数を常に表示します。
- **レスポンシブ対応**：タブレットの横／縦画面、スマートフォンの狭い画面でもレイアウトが崩れません。
- **うっかり防止**
  名前が未入力のまま提出しようとすると警告が出ます。先生と接続していない状態では提出できません（送信できていないのに提出済になってしまう事故を防ぎます）。新規作成時は学年・クラス・名前を引き継ぎます。
- **ネットがなくても書ける**
  入力内容は自動で端末に保存されます。作文は `.json` ファイルとして書き出し／読み込みもできるので、通信が使えない環境や端末の乗り換えにも対応できます。

### 👩‍🏫 先生用の添削ツール

- **なぞるだけの赤ペン**
  原稿用紙プレビュー上で直したい文字をマウスや指でドラッグすると、その範囲にコメントを付けられます。付けた添削は即座に児童の画面に反映され、児童は読んだあと「修正完了」で赤線を自分で消せます。
- **AI自動添削アシスト（Gemini API）**
  Google の `gemini-2.5-flash` を使い、誤字脱字の指摘と「児童の思考を促す問いかけ」を自動生成して赤ペンとして貼り付けます。AIに送るのは**学年・題名・本文のみで、児童の名前は送信しません。**
- **差分ビュー**
  前回添削した時点の文章と今の文章を比べ、児童が**書き足した部分を青**、**消した部分を赤の取り消し線**で表示します。どこを直したのかが一目で分かります。
- **名簿の絞り込み**
  キーワード（名前・題名・本文）、状態（完了以外／すべて／提出済／再提出／完了）、更新日の範囲で一覧を絞り込めます。
- **一括操作**
  チェックを入れた作文をまとめて「AI添削」「完了」「印刷」できます。
- **A4横の原稿用紙で印刷**
  1枚に見開き2面＋中央の行罫（題名・ページ番号入り）を配置した、本物に近いレイアウトで印刷できます。
- **キーボードショートカット**
  児童の切り替え、完了／再提出、AI添削、印刷などをキー操作で行えます（`?` キーで一覧を表示）。
- **パスワード保護（任意）**
  先生用設定でパスワードを決めると、以後は先生モードに入る際に入力が必要になります。**初期状態はパスワードなしで誰でも先生モードに入れます。**

### 📲 PWA対応（アプリとしてインストール可能）

- **ホーム画面に追加**：画面右上の「**追加**」ボタンから、PC・タブレット・スマホにインストールできます（Chrome / Edge のアドレスバーに出るインストールボタンからでも同じです）。iPad / iPhone の Safari は「インストール」の合図を出さない仕様のため、「追加」を押すと「共有 → ホーム画面に追加」の手順が画面に出ます。手順は [MANUAL.md の第9章](MANUAL.md#9-アプリとして端末に入れるホーム画面に追加) を参照してください。
- **オフライン起動**：一度読み込んだあとは Service Worker のキャッシュにより、ネットワークがなくてもアプリを起動して作文を書けます（P2P通信とAI添削にはネットワークが必要です）。キャッシュが無い状態で圏外アクセスした場合は `offline.html` が表示されます。
- **更新の通知**：新しい版を配ると、児童の画面に「あたらしい バージョンが あります」という帯が出ます。**押されるまで入れ替わりません**（作文を書いている最中に中身が変わらないようにするため）。
- **アプリ識別子**：`manifest.webmanifest` の `id` / `scope` / `start_url` は `/online-manuscript-paper-pro/` の**絶対パス**で固定しています。`gigayama.github.io` は多数のアプリが同一オリジンを共有しているため、ここを相対パス（`./`）にすると別アプリと同じ識別子になり、「開いたら違うアプリが立ち上がる」事故の原因になります。**このリポジトリをコピーして別アプリを作る場合は、まずこの3つを書き換えてください。**

## 🚀 導入・デプロイ方法

本アプリは `index.html` を中心とした**静的ファイルのみ**で構成されています。ビルド作業は不要です。

1. 本リポジトリをダウンロード、またはフォークします。
2. **GitHub Pages** やお好きなWebホスティング（Vercel, Netlify, 学校内サーバーなど）に、以下のファイルをそのままアップロードします。
   ```
   index.html
   offline.html
   manifest.webmanifest
   sw.js
   favicon.png
   icons/
   ```
3. 公開されたURLにアクセスすればすぐ使えます。

> **HTTPS での公開を推奨します。** PWAのインストール・オフライン動作（Service Worker）と、P2P通信（WebRTC）は HTTPS 環境が前提です。

本リポジトリには GitHub Actions のワークフロー（`.github/workflows/deploy-pages.yml`）が含まれており、`main` ブランチへの push で GitHub Pages に自動デプロイされます。

### 品質ゲート

デプロイの前に、GIGA Standard v4 の要件を機械的に検査します。手元でも実行できます。

```bash
node scripts/check-project.mjs
```

一度直した項目（`manifest` の `id`、`sw.js` のキャッシュ削除範囲、`100vh` の単独使用など）を、あとの改修で静かに壊し戻していないかを見張るためのものです。**落ちた場合は検査を緩めず、`quality.config.json` の `securityExceptions` に理由を書いて明示的に許可してください。**

> **AI添削を使う場合:** 先生モードの「設定（歯車マーク）」から、ご自身の **Gemini APIキー** を登録してください。キーは先生のブラウザ内（localStorage）にのみ保存され、リポジトリやサーバーには送信されません。

## 📖 かんたんスタートガイド

くわしい手順・画面の説明は [MANUAL.md](MANUAL.md) を参照してください。

### 👩‍🏫 先生（ホスト）

1. アプリを開き、右上の「**先生用**」ボタンで先生モードに入ります。
2. 左パネルの「**通信ルームを開始**」を押します。
3. 表示された **4桁のPINコード** を児童に伝えます（接続人数もここに表示されます）。
4. 児童が「**提出**」すると、左の名簿に作文が並びます。
5. 名簿から選ぶと右に原稿用紙が出ます。文字をドラッグして添削するか、「**AI添削**」を使います。
6. 「**再提出**」または「**完了**」を押すと、接続中の児童の画面へ即座に反映されます。

### 🧒 児童（クライアント）

1. アプリを開き、画面上部の「**先生と接続**」（鎖のマーク）を押します。
2. 先生に教えてもらった **4桁のPIN** を入力します。
3. 題名・学年クラス・名前を入れて、作文を書きます。
4. 書けたら「**提出**」を押します（接続していないと提出できません）。
5. 先生から返ってくると右上の「**ベルのマーク**」に未読の数が付きます。押してコメントを読み、赤い部分を直します。

## 🛠 技術スタック

| 分類 | 使用技術 |
| --- | --- |
| UI | React 18（UMD版）＋ Babel Standalone（JSXをブラウザ内で変換） |
| スタイル | Tailwind CSS（CDN版）、Bootstrap Icons、Google Fonts（Zen Maru Gothic / Shippori Mincho / Zen Old Mincho） |
| P2P通信 | PeerJS 1.5.2（WebRTC） |
| 差分表示 | diff-match-patch |
| AI添削 | Google Gemini API（`gemini-2.5-flash`） |
| ダイアログ | SweetAlert2 |
| オフライン | Service Worker（`sw.js`）＋ Web App Manifest |
| データ保存 | ブラウザの localStorage |

いずれのライブラリもCDNから読み込むため、**初回アクセス時のみネットワーク接続が必要**です。2回目以降は Service Worker のキャッシュで起動できます。

## 🔐 セキュリティ設計（このアプリが「守っていること」と「守っていないこと」）

サーバーを持たない構成のため、**サーバー側で認証・認可を行う余地がありません。**
何をもって安全としているかを明記します。導入判断の材料にしてください。

### 守っていること

| 項目 | 設計 |
| --- | --- |
| 作文データの置き場所 | 各端末の `localStorage` のみ。開発者や作者のサーバーには一切送信しません |
| 端末間のやり取り | WebRTC による端末どうしの直接通信（P2P）。**中継サーバーに作文の中身は残りません** |
| 受信データの扱い | P2P で受け取った内容・ファイルから読み込んだ内容は、必ず `normalizeDraft()` で形を整えてから使います。壊れたデータや細工されたデータで画面が壊れないようにするためです |
| Gemini APIキー | 先生の端末の `localStorage` にのみ保存。ソースコードに直書きしていません |
| Service Worker | 自アプリ接頭辞（`genko-pro-`）のキャッシュだけを削除します。同一オリジンの他アプリを巻き添えにしません。`localStorage` には一切触れません |
| ブラウザ保存領域 | 他アプリと共有する `study.records.v1` を含め、自アプリ接頭辞（`genko_pro_`）以外のキーを読み書き・削除しません。`localStorage.clear()` は使いません |

### 守っていないこと（運用でカバーが必要）

| 項目 | 実態 |
| --- | --- |
| **PINは「宛先」であって「認証」ではありません** | 4桁のPINは、どの先生につなぐかを指し示すだけのものです。PINを知っている人は誰でもそのルームに接続できます。**授業時間外はルームを閉じてください** |
| **先生モードのパスワードは端末内の照合です** | 初期状態は**パスワードなしで誰でも先生モードに入れます。**照合は端末内で行うため、端末を触れる人には突破されうる想定です。児童に配る端末では、必ずパスワードを設定してから配布してください |
| **画面の出し分けは防御ではありません** | ボタンが見えないことと、操作できないことは別です。児童用端末の管理（MDM・キオスクモード等）と併用してください |
| **AIには本文がそのまま送られます** | 送信されるのは学年・題名・本文です。氏名は送りませんが、**本文中に個人が特定できる記述があればそのまま送信されます** |
| **CSP（Content-Security-Policy）は未設定です** | 現在の構成はブラウザ上で JSX を変換しているため、実効性のある CSP を書けません（`unsafe-eval` と `unsafe-inline` が必須になり、制限として機能しません）。詳細は `AUDIT.md` の §H2 を参照してください |

> **個人情報の観点でのおすすめ運用**
> 「名前」欄は出席番号やニックネームでも動作します。学校の方針に応じて使い分けてください。

## ⚠️ 注意事項・制限事項

### データの保存について

- データは**開いているブラウザの中（localStorage）にのみ**保存されます。**別の端末・別のブラウザで開くと、過去のデータは表示されません。**
  別の端末で続きを書く場合は、必ず「ファイル（`.json`）」に書き出し、新しい端末の「開く」→「ファイルから読み込む」で取り込んでください。
- 先生のPCでブラウザの履歴・サイトデータを消去すると、**保存されていた児童の提出データも消えます。** 長期保存が必要な場合は、印刷またはファイルのダウンロードでバックアップしてください。
- 端末の保存領域がいっぱいの場合やプライベートモードでは保存に失敗することがあります。その場合は画面に警告が表示されます。

### 通信について

- 作文データそのものは端末間で直接（P2P／WebRTC）やり取りされますが、**接続の仲介にはPeerJSの公開シグナリングサーバーを利用します。** 学校のネットワークでWebRTCや当該サーバーが遮断されていると接続できません。
- PINは4桁のため、**別の教室と偶然同じPINになる可能性があります。** 重複を検知した場合は自動的に別のPINで再取得しますが、授業中は先生の画面に出ているPINが正しいことを都度確認してください。
- 先生が「通信ルームを開始」していない間、児童は接続も提出もできません。

### 上限のめやす（クォータ）

数値はブラウザや提供元の仕様で変わります。**授業前に一度、実際の環境で試すことを強くおすすめします。**

| 対象 | めやす | 超えたときに起きること |
| --- | --- | --- |
| `localStorage`（1オリジンあたり） | おおむね **5MB** | 保存に失敗し、「この端末に保存できませんでした」と画面に出ます。作文は日本語で1文字あたり数バイトなので、通常の学級運用で到達することはほぼありませんが、**先生の端末には全児童分がたまる**点に注意してください |
| 先生1人あたりの同時接続 | **1クラス（40人程度）を想定** | 端末の性能とネットワーク次第です。うまく届かない児童が出た場合は、時間をずらして提出させてください |
| PINコード | **4桁** | 別の教室と偶然重なることがあります。重複を検知した場合は自動で取り直しますが、画面に出ているPINを都度確認してください |
| PeerJS シグナリングサーバー | 公開の共用サーバー | 提供元の都合で停止・制限されることがあります。停止時は「ファイルでのやりとり」（`.json` の書き出し／読み込み）で代替できます |
| Gemini API | 契約しているプランの上限 | 上限に達すると AI添削だけが失敗します。手動の赤ペン添削は影響を受けません |
| iOS Safari の保存データ | **7日間未使用で消去される場合あり**（ITP） | 作文が消えます。**ホーム画面に追加**しておくと受けにくくなります。大事な作文は `.json` に書き出してください |
| 初回に読み込むファイル | CDN 由来を含めおよそ **3MB**（うち Babel が約 2.9MB） | 校内Wi-Fiが混んでいると初回表示が遅くなります。2回目以降はキャッシュから起動します。詳細と改善案は `AUDIT.md` §H1 を参照してください |

### AI添削について

- Gemini APIキーは先生ご自身で用意し、利用規約・利用料金をご確認のうえお使いください。
- AIに送信されるのは**学年・題名・本文**です。児童の名前は送信しませんが、**本文中に個人が特定できる情報が書かれている場合はそのまま送信されます。** 運用ルールにご注意ください。
- AIが指摘した箇所は、本文中に該当する文字列が見つかった場合のみ赤ペンとして貼り付けられます。そのため提案の一部が反映されないことがあります。
